# FX Chain System

The master reference for every FX chain in the template — the routing model, the theory behind chain order, the conventions every chain note follows, and the index of all chains. Built around the actual rig: Apollo MkII + UAD Console (Unison), Ableton Live Suite, the [[Plugin Index]] collection, [[Neumann TLM 102]] + [[Shure SM57]], Strat / Yamaha acoustic / Hofner bass.

## The routing model

```
TRACK ──→ GROUP ──→ BUS ──→ MASTER
  │          │        │
  └──────── sends ────┘──→ RETURNS ─┬─ dedicated to one family ──→ that family's BUS
                                    └─ shared / mix-wide ───────→ MASTER
```

**Division of labor — each level exists to answer a different question:**
- **Track** — "what does this *sound* like?" Corrective + character work on one source. The only level where surgery belongs.
- **Group** — "how do these tracks relate *to each other* and to the other groups?" Carving, internal balance, section glue. (Steps 4–5 of the process.)
- **Bus** — "what's the *finish* on this section?" Broad, gentle, analog-flavored: glue comp, tape, density. If you reach for surgery at bus level, the fix belongs upstream.
- **Returns/sends** — shared spaces and parallel treatments (reverbs, delays, crush, dirt, width). Shared = coherent: everyone in the same room, one dirt flavor, blendable per-track via send levels.
  - **Return routing rule:** a return that serves ONE family routes into that family's bus ([[Delay Send Slap]], [[Delay Send Other]], [[Reverb Send Long]] → [[3 Vocal Bus|Vocal Bus]]) — the bus glue melts wet into dry, and a bus fader ride carries the space with the voice. A return shared mix-wide ([[Reverb Send Room]], [[Saturation Send]], [[Width Send]], [[Parallel Comp Send]]) stays → master — folding it into any one bus would drag every other sender through that bus's chain. Handle shared returns *at the return* (band-limit, duck); the [[Master Chain]] is the only processing they pass through, and that's correct.
- **Master** — the final 10%. ±1–2 dB moves only; two modes (mix-into-it vs export loudness) — see [[Master Chain]].

## The recording process (6 steps)

1. **Input** — external sources through the Apollo: Unison preamp + UAD comp + UAD EQ printed on the way in, like tracking to analog. *Conservative*: 2–4 dB GR peaks-only, HPF + a dB of air max — you can always add later, never remove. Internal/digital sources get the UAD plugin equivalents in Ableton (no Unison impedance magic, same gain-staging discipline) — digital instruments are still instruments.
2. **Initial processing** (bounce-in-place) — corrective EQ, de-noise, first saturation. Commit when dialed.
3. **Track effects** — character, delays/reverb sends, per-track color. Bounceable once stable.
4. **Group processing** — EQ *against the other tracks/groups*: decide what stands out, cut the interference **from the other group**, not by boosting yourself.
5. **Group effects** — section-level glue/width/duck.
6. **Bus + master** — finish and loudness.

## Core principles (the theory the chains are built on)

**Chain order: corrective EQ → compression → saturation/color → tonal EQ → de-ess/cleanup.**
- *Cuts before compression* — the comp shouldn't waste its GR chasing rumble and mud you're throwing away anyway.
- *Saturation after compression* — a leveled signal hits the saturator consistently, so the color is even across the performance. (Exception: 808s/sound design, where saturation *generates* the tone — see [[1 Digital Bass Track|Digital Bass Track]].)
- *Boosts after compression* — boost before and the comp just compresses your boost back down.
- *De-ess/soothe last* — sibilance and harshness are regenerated by every comp and saturator; clean up after the mess is made, not before.

**Gain staging: ~0 VU (≈ −18 dBFS) into everything.**
- Analog-modeled plugins (UAD, Decapitator, Kramer, API-2500…) are calibrated to hardware sweet spots — hit them at −18 dBFS average and they sing; slam them and they choke.
- **Meter sandwich convention:** [[Utility]] (gain in) + [[mvMeter2nogpu]] (VU) at the chain head, Utility (trim) + meter at the tail, extra meters between sections on long chains. Target ~0 VU average; peaky sources (drums) average 0 with peaks flying; background elements can run looser.
- **Unity through every device:** set each device's output so bypassing it doesn't change loudness — otherwise "louder = better" psychoacoustics fools you on every single knob decision.

**Compression in stages, never in one bite.**
- Tracking 1176 (2–4 dB peaks) → track comp (3–5 dB shape) → group/bus glue (1–2 dB) beats one 10 dB squash: each stage works gently, so none of them pump. The record ends up *more* controlled and *more* dynamic-feeling at once.

**Serial vs parallel.**
- Serial (inserts) trades dynamics for control. Parallel (sends: [[Parallel Comp Send]], [[Saturation Send]], [[Width Send]]) adds density/size *without* the trade — dry keeps the transients, the return brings the wreckage underneath.

**Space is EQ'd, ducked, and shared.**
- Returns run 100% wet, band-limited (HPF 200–300, LPF 4–8k) — space without spectral cost.
- Pre-delay 15–25 ms separates dry from tail = upfront *and* placed.
- Big tails duck under the dry vocal (sidechain) = size without smear.
- Low end never gets reverb, never gets width, and lives in mono below ~100–120 Hz.

**The masking hierarchy.** Every carve decision flows from one ranking: **lead vocal → drums backbeat/kick → bass → hooks/leads → everything else.** When two elements collide, the lower-ranked one moves (dip, duck, pan, or drop an octave). Dynamic EQ keyed from the winner beats static carves — full sound when alone, automatic space when it matters.

## Note format (Producer Pal phase 2 contract)

Every chain note is machine-parseable for future Producer Pal automation:
- **Frontmatter:** `type: chain` · `chain_type: track|group|bus|send|master|style|foundation` (`foundation` = a reusable neutral front-end block prepended to a family's track chains before role/character decisions — currently [[0 Vocal Foundation|Vocal Foundation]]) · `family` · `source` · `routing` · `uad_console` (the Step 1 recording chain — Unison preamp, UAD compressor, UAD EQ; UAD-plugin-equivalent front end on digital sources) · `signal_chain` (ordered Ableton device list, musical devices only — the meter sandwich is implied by this doc)
- **Section structure (track chains — the 6-part standard, 2026-07-16):** `## 1 — Recording Setup` (mics/DI, placement, room, monitoring, gear links) → `## 2 — Tracking Best Practice` (double-track or not, mono/stereo, take-stacking variations — the decisions that shape the mix later) → `## 3 — Source → Ableton (UAD Console)` (Unison preamp + UAD comp + UAD EQ printed on the way in; software instruments swap this for instrument choice + UAD-equivalent front end) → `## 4 — Ableton Initial Processing` (corrective/bounceable) → `## 5 — Track FX (optional)` → `## 6 — Bus / Send FX (optional)` (routing + send levels). Every UAD plugin name starts with **UAD** and links to its plugin note ([[UAD UA 610-B]], [[UAD Teletronix LA-2A]], [[UAD Pultec EQP-1A]], [[UAD UA 1176LN]], [[UAD Neve 1073]]) so console-side vs Ableton-side is unambiguous. Every named plugin/gear/technique is a `[[wikilink]]`, and every adjusted parameter gets a concrete starting value. **ALL track chains converted (2026-07-16).** Software-instrument chains use the adapted parts — `## 1 — Sound Selection` (instrument/sample choice IS the recording step) and `## 2 — Programming Best Practice` — and their §3 is `Source → Ableton (UAD front end)`: no mics, but the UAD plugins still act as the console input (preamp → comp → EQ, printed at ~0 VU), so digital sources get the same tracking discipline as recorded ones.
- **Body grammar:** stages are `### N. [[Device Name]] — role`, settings as bullets beneath, rationale on a `**Why:**` line. Device names match Live's Device Lister names where possible (`UAD UA 1176LN Rev E`, etc.).
- Phase 2: Producer Pal reads `signal_chain` + stage headings → instantiates devices in order on the right track/group/return → applies starting-point settings → human fine-tunes (`uad_console` is console-side, listed for the human).
